# PWA 告警卡与证据舱联动设计

日期：2026-03-18

## 目标
在现有“告警矩阵 -> 证据舱”结构上，进一步建立卡片与详情舱之间的视觉联动，让用户明确知道：

- 当前正在查看哪一条告警
- 当前证据舱处于空态、详情态还是取证完成态

## 范围
- 调整 `apps/pwa/src/app.js` 中告警卡与证据舱的展示状态类
- 调整 `apps/pwa/src/styles.css` 中告警卡选中态、证据舱载入态和取证态样式
- 在 `apps/pwa/tests/cyber_ui_upgrade.test.js` 中补充联动状态相关断言

## 非目标
- 不修改接口调用
- 不修改告警处理、取证、加载详情的业务流程
- 不新增全局状态管理方案

## 当前问题
当前告警卡和证据舱已经有结构层级，但缺少明确联动：
- 点击 `详情` 后，用户无法从告警矩阵中一眼定位“当前选中的告警”
- 右侧证据舱虽然会加载内容，但视觉上没有明显的“已装载”状态
- 点击 `取证` 后，也没有让用户直观感知“当前证据包与哪条告警关联”

## 备选方案

### 方案 A：轻量状态类联动
在现有交互函数里添加少量 DOM 状态类：
- 告警卡：`is-selected`
- 证据舱：`is-loaded`、`is-evidence`

优点：
- 风险最低
- 不需要改业务逻辑
- 联动感提升最直接

### 方案 B：重做告警详情数据映射
把详情舱改成结构化字段映射而不是纯 JSON。

优点：
- 视觉可读性更强

问题：
- 这一轮范围过大
- 更接近功能层改造

### 方案 C：仅做 hover 和过渡
不做真实联动状态，只增强 hover。

优点：
- 最快

问题：
- 无法解决“当前看的是哪条告警”这个根问题

## 结论
采用方案 A。

## 设计方案

### 1. 告警卡选中态
当用户点击：
- `详情`
- `取证`

对应告警卡进入 `is-selected` 状态。

视觉特征：
- 边框更亮
- 主动作更聚焦
- 卡片表面出现轻微激活高光

### 2. 证据舱联动态
证据舱新增两类状态：
- `is-loaded`
  - 当 `loadAlertDetail` 成功后进入
- `is-evidence`
  - 当 `generateEvidence` 成功后进入

视觉特征：
- `is-loaded` 更像“详情已接入”
- `is-evidence` 更像“证据包已生成”

### 3. 联动边界
实现方式尽量轻量：
- 不新增复杂状态对象
- 只通过 DOM 查询和类名切换实现
- 尽量复用当前 `alert.id` 和现有按钮事件

### 4. 失败与空态
如果加载失败，不保持误导性的激活态：
- 告警卡不应永久保留错误激活
- 证据舱不应维持错误状态类

## 技术约束
- 允许在 `app.js` 中增加小型展示辅助函数
- 不允许更改 `fetchJson`、API path 或 action 语义
- 保留现有 `data-action`
