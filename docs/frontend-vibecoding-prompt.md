```md
你是一名资深前端工程师、创意技术导演和 UI/UX 设计师。请为「外卖取餐防盗全链路监控系统」完成一个高质感、可运行、可维护的前端体验。不要做通用模板页，不要只给方案，直接落地成代码。

## 0. 项目信息

项目名称：Takeout Guard / 外卖取餐防盗全链路监控
项目类型：SaaS Dashboard / PWA 控制台 / 边缘设备监控平台
一句话目标：帮助校园、公寓楼、集中取餐点用户实时监控外卖取餐过程，识别异常取餐，自动留存证据并推送告警。
目标用户：经常点外卖且担心被误拿或偷拿的个人用户、宿舍楼/公寓运营方、集中取餐点管理员、设备运维人员。
品牌气质：精密、冷静、可信、边缘智能、轻微赛博但不浮夸；像一个真正用于值守和复盘的安全中枢。
核心业务：订单导入、送达布防、边缘设备心跳、摄像头/重量传感事件、规则引擎、异常告警、证据包、报表、规则 DSL 配置、实时 WebSocket 更新。

后端接口默认基地址：

- REST：`http://localhost:18000/api/v1`
- WebSocket：`ws://localhost:18000/ws/alerts`

## 2. 总体目标

我要的不是营销落地页，而是第一屏就能工作的监控控制台。首屏必须让用户直接看到：

- 当前防护状态
- 活跃订单和最新监控会话
- 在线/离线边缘设备
- 最新告警
- 传感器事件流
- 规则命中状态
- 核心操作：导入订单、启动防护、确认取餐、查看证据、导出报表

请同时做到：

- 视觉上有明确记忆点，第一眼能看出这是“外卖取餐防盗 + 边缘智能监控”系统。
- 信息密度高但不乱，优先扫描效率、状态区分和快速处理。
- 工程上组件边界清楚，接口层、状态层、视觉组件、图表组件、实时事件处理分离。
- 响应式完整，桌面端像值守中枢，移动端像随身告警处理工具。
- 动效和 3D 只服务监控语义，不做无意义炫技。

## 3. 视觉方向

选择「冷静值守中枢 + 边缘感知雷达」作为主审美方向。

### 色彩

建立 CSS/Tailwind token，不要大面积紫蓝渐变。

- 主背景：深墨黑 `#080B0D`
- 次级背景：炭灰 `#11171A`
- 工作面板：冷灰黑 `#151C20`
- 主视觉青绿：传感器青 `#38D5C8`
- 告警强调：危险朱红 `#E64B3C`
- 证据高亮：琥珀金 `#D89A3A`
- 安全状态：低饱和绿 `#67B26F`
- 文本主色：雾白 `#F2F5F3`
- 文本次色：冷灰 `#9AA8A8`

### 字体

- 英文/数字标题：`Instrument Serif` 或 `Editorial New` 风格字体，用于少量大标题和关键数字。
- 中文标题：优先思源宋体/霞鹜文楷一类有识别度但可读的字体。
- 正文和控制台标签：使用清晰耐读的无衬线字体；如果使用 Inter，必须只作为功能字体，不能让整站变成默认 SaaS 模板。
- 数字和状态码：使用等宽字体，适合扫描设备 ID、事件时间、规则命中次数。

### 视觉母题

主视觉母题是“取餐架俯视雷达 + 传感器热区 + 证据光锥”。

首屏背景使用 Three.js + GLSL Fragment Shader 做一个非常克制的实时感知场：

- 深色背景上有低亮度的取餐架平面轮廓。
- 青绿色扫描线以 12 秒周期缓慢扫过，像边缘设备在检测 ROI 区域。
- 当出现告警状态时，局部区域从青绿过渡到朱红，并出现短促脉冲。
- 使用细微 film grain，密度低，不要脏。
- 使用轻量噪声和距离场，不要做漂浮光球、无意义网格或玻璃拟态大卡片。
- 支持 `prefers-reduced-motion`，移动端降低粒子/扫描复杂度。

## 4. 记忆点：证据光锥光标

设计一个贯穿工作台的主记忆交互：证据光锥光标。

- 默认鼠标仍保留系统可用性，但在主工作区叠加一个极轻的“扫描光锥”跟随指针。
- Hover 到订单、告警、设备、证据卡片时，光锥变窄并出现取证边框，像摄像头锁定目标。
- Hover 到危险告警时，光锥边缘出现 1 次朱红脉冲。
- Hover 到可导出证据区域时，光锥出现琥珀色高光。
- 该效果用 CSS + Canvas/WebGL 均可，但必须性能稳定；低性能或移动端降级为简单 focus ring。

## 5. 信息架构

请实现一个完整控制台，不要只做上半屏。

### 5.1 全局布局

- 左侧固定导航：概览、订单、防护会话、告警、设备、规则、证据、报表、运维。
- 顶部状态栏：系统在线状态、WebSocket 连接状态、后台任务状态、当前用户、刷新/导出快捷操作。
- 主内容区域：默认进入「实时概览」。
- 右侧可选详情抽屉：点击订单/告警/设备后显示上下文详情。

### 5.2 实时概览页

必须包含：

- 防护状态总览：活跃会话、在线设备、未处理告警、24h 事件数。
- 取餐防护地图：用抽象货架/ROI 网格展示订单位置、设备状态、异常热区。
- 最新订单队列：订单状态、送达时间、预计取餐截止、最新会话。
- 告警处理队列：告警级别、触发规则、状态、证据入口、确认/忽略/解决操作。
- 传感器事件流：motion、weight_drop、object_missing 等事件按时间滚动。
- 规则命中面板：展示规则名、优先级、是否 suppressed、冷却状态。

### 5.3 订单页

- 支持订单列表、筛选、状态标签、导入订单、手动布防、确认取餐。
- 订单详情展示状态时间线：created、delivered、armed、alerted、picked_up。
- 如果订单已关联监控会话，展示会话状态和设备信息。

### 5.4 告警页

- 告警列表必须支持级别、状态、时间、规则、设备筛选。
- 告警详情展示触发事件、规则命中、证据素材、处理记录。
- 操作状态要完整：acknowledge、resolve、false positive。

### 5.5 设备页

- 展示设备在线/离线、最近心跳、配置版本、队列大小、应用配置时间。
- 设备卡片不要做营销卡片，应该像真实运维面板。
- 设备详情包含 ROI 配置、sensitivity 配置、最近事件。

### 5.6 规则页

- 实现规则集列表、规则优先级、事件类型、条件 DSL、action、cooldown。
- DSL 编辑器要可读，不要只暴露 JSON 文本框。
- 需要有 validate、preview、保存、禁用、复制规则等交互。

### 5.7 报表页

- 展示订单、告警、设备、会话、事件、规则命中的趋势。
- 支持 day/week、日期范围、导出 CSV。
- 图表风格要克制，适合扫描；不要用彩虹色。

### 5.8 证据页

- 展示证据包、媒体素材、manifest、生成状态。
- 证据卡片要强调可信性：时间戳、hash、事件链路、来源设备。

## 6. 数据与接口要求

请优先对接现有 FastAPI 接口；如果某些接口暂时缺失，使用清晰的 mock adapter，保证之后容易替换。

接口层需要集中管理：

- 认证：登录、注册、token 刷新或保持
- 订单：列表、创建/导入、布防、确认取餐、导出
- 告警：列表、处理、状态更新
- 设备：列表、配置、心跳展示
- 规则：规则集、规则 CRUD、DSL validate/meta/fields/evaluate
- 报表：summary、trends、rule matches export
- 证据：证据包、媒体、导出
- 实时：WebSocket 订阅和事件路由

必须处理：

- loading
- empty
- error
- offline
- WebSocket reconnecting
- stale data
- permission denied
- export failed
- reduced motion

## 7. 动效规则

动效要像值守系统，不要像展示站。

主记忆动效：

- 首屏/概览背景的传感器扫描 Shader
- 证据光锥光标
- 告警脉冲只在状态变化时出现

微交互：

- 列表新增事件进入时轻微滑入，不要整体跳动。
- 告警从 open 变 resolved 时做短暂状态过渡。
- 规则验证通过/失败要有明确反馈。
- 抽屉打开使用 GSAP，时长控制在 180-260ms。
- hover 不得改变布局尺寸。

所有动画必须支持 `prefers-reduced-motion` 降级。

实现要求：

- TypeScript 类型清楚，禁止把核心接口都写成 `any`。
- API client 支持超时、错误归一化、鉴权 header、Blob 导出。
- WebSocket 模块要处理订阅、重连、节流、事件分发。
- 状态管理可使用 React 内置状态或轻量 store；不要为了小项目引入过重依赖。
- 样式使用 Tailwind + CSS variables，设计 token 集中维护。
- 固定格式元素必须设置稳定尺寸，例如仪表盘、表格行、状态徽标、图表容器、工具栏。
- 图标使用 lucide-react，不要手写一堆 SVG。
- 不要卡片套卡片，不要所有区块都浮起来。
- Dashboard 第一屏必须是真工作界面，不要做大口号 hero。
